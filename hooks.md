- Хук — моя команда, которую Claude Code запускает сам на определённом событии: перед вызовом инструмента, после правки файла, когда Claude ждёт ответа.
- Срабатывает всегда и одинаково, от решения модели не зависит. Это и отличает его от просьбы в [CLAUDE.md](_CLAUDE.md.md), см. [какое расширение выбрать](какое%20расширение%20выбрать.md).
- `/hooks` — посмотреть все хуки по событиям.
- Можно попросить Claude написать хук словами.
- Главные события
	- `PreToolUse` — перед вызовом инструмента. Может запретить вызов.
	- `PostToolUse` — после успешного вызова. Отменить уже ничего не может.
	- `UserPromptSubmit` — я отправил запрос, Claude его ещё не видел.
	- `Notification` — Claude ждёт ответа или разрешения.
	- `Stop` — Claude закончил отвечать.
	- `SessionStart` / `SessionEnd` — начало и конец сессии.
	- `PreCompact` / `PostCompact` — до и после сжатия контекста, см. [/compact](!compact.md).
	- `SubagentStart` / `SubagentStop` — [субагент](subagents.md) запущен и закончил.
	- Полный список — больше 30 событий — в документации.
- Как записать
	- В `hooks` в [settings.json](_settings.json.md): событие → `matcher` → список команд.
	- `matcher` — на что реагировать. Для инструментов это имя: `Bash`, `Edit|Write`, `mcp__.*`. Пустой — на всё.
	- Пример — уведомление на рабочем столе, когда Claude ждёт меня (Linux):
		```json
		{
		  "hooks": {
		    "Notification": [
		      {
		        "matcher": "",
		        "hooks": [
		          {
		            "type": "command",
		            "command": "notify-send 'Claude Code' 'Claude ждёт ответа'"
		          }
		        ]
		      }
		    ]
		  }
		}
		```
	- `if` — фильтр точнее, чем `matcher`, в синтаксисе правил разрешений: `"if": "Bash(git *)"` — только git-команды.
- Как хук общается с Claude Code
	- На вход, в stdin, получает JSON о событии: `tool_name`, `tool_input`, `session_id`, `cwd`.
	- Отвечает кодом выхода:
		- `0` — возражений нет. Для `PreToolUse` это не разрешение: дальше обычная проверка прав.
		- `2` — запретить. Текст из stderr уходит Claude, и он пробует по-другому.
		- другой код — ошибка хука, но действие выполняется.
	- Для тонкой настройки — выйти с `0` и напечатать в stdout JSON: разрешить, запретить, спросить меня, добавить текст в контекст.
	- У `SessionStart` и `UserPromptSubmit` обычный вывод в stdout попадает в контекст Claude.
- Типовые хуки
	- Форматирование после правки: `PostToolUse` + `Edit|Write` → `jq -r '.tool_input.file_path' | xargs npx prettier --write`.
	- Защита файлов: `PreToolUse` + `Edit|Write` → скрипт проверяет путь и выходит с `2` на `.env`, `.git/`.
	- Напомнить важное после сжатия контекста: `SessionStart` с `matcher: "compact"` → `echo 'используй pnpm, не npm'`.
	- Уведомление, когда Claude ждёт — пример в «Как записать».
- Где хранить
	- `~/.claude/settings.json` — для меня во всех проектах.
	- `.claude/settings.json` — для проекта, коммитится.
	- `.claude/settings.local.json` — для меня в этом проекте.
	- В [плагине](плагины.md), в [skill](skills.md) или в настройках субагента — работают, пока те включены или запущены.
	- Скрипты удобно класть в `.claude/hooks/` и вызывать через `"$CLAUDE_PROJECT_DIR"/.claude/hooks/имя.sh`. Не забыть `chmod +x`.
	- Выключить все — `"disableAllHooks": true`.
- Кроме команд
	- `type: "prompt"` — решение принимает модель по моему промпту. Например, `Stop`: «всё ли сделано? если нет — продолжай».
	- `type: "agent"` — то же, но субагент может читать файлы и запускать команды. Экспериментально.
	- `type: "http"` — отправить JSON события на URL.
- Осторожно
	- Хук — любой код на моей машине с моими правами. Чужие хуки из репозитория или [плагина](плагины.md) — сначала прочитать.
	- Запрет из `PreToolUse` работает в любом [режиме](режимы.md), даже когда разрешения пропускаются. А «разрешить» из хука не перебьёт `deny` из settings.json.
	- Claude может менять файлы и через `Bash`, а не только `Edit`/`Write`. Хук на `Edit|Write` такие правки не увидит.
	- Хуки с одним событием запускаются параллельно, порядок не гарантирован.
- Советы
	- Начинать с простого: уведомление, когда Claude ждёт, и форматирование после правки.
	- Хук заводить, когда просьба в `CLAUDE.md` соблюдается не всегда, а нужно — всегда.
	- Хук должен быть быстрым: он запускается на каждое событие.
	- Проверять скрипт отдельно, подав JSON руками: `echo '{"tool_input":{"file_path":"a.ts"}}' | ./hook.sh`.
	- Сработал ли хук и что вывел — `claude --debug` или `Ctrl+O`.
	- В запрещающем хуке писать в stderr понятно: что не так и что делать вместо. Это читает Claude.
