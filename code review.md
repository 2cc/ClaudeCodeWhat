- `/code-review` — ищет баги в изменениях. Встроенный [skill](skills.md).
- `/review` — то же самое, другое имя.
- `/security-review` — ищет уязвимости.
- `/simplify` — не баги, а чистка кода.
- /code-review
	- По умолчанию смотрит коммиты ветки, которых нет в upstream, плюс незакоммиченное. Нет изменений — нечего смотреть.
	- Другая цель — передать аргументом: путь к файлу, номер PR, ветку или диапазон `main...my-feature`.
	- Работает в фоне как [субагент](subagents.md): свой контекст, беседу не забивает. Находки приходят в беседу, когда готово.
	- Учитывает `CLAUDE.md`.
	- Claude может запустить его и сам, если попросить словами «посмотри мои изменения».
	- Уровень
		- `/code-review low` … `max` — тот же [/effort](!effort.md).
		- `low`, `medium` — только то, в чём уверен. Меньше ложных срабатываний.
		- `high` … `max` — шире, но может быть и неуверенное.
		- Без уровня берёт последний, который вводил руками, даже в прошлой сессии.
	- Флаги
		- `--fix` — сразу применить исправления.
			- Эти правки [/rewind](!rewind.md) не откатит, только git.
		- `--comment` — оставить находки комментариями в PR на GitHub или в MR на GitLab.
	- ultra
		- `/code-review ultra` (старое имя `/ultrareview`) — глубокое ревью в облаке несколькими агентами.
		- Сравнивает текущую ветку с основной, плюс незакоммиченное.
		- На Pro и Max — 3 бесплатных запуска, дальше платно.
		- Нужен вход через аккаунт claude.ai.
- /security-review
	- Смотрит разницу между текущей веткой и основной веткой на `origin`.
	- Ищет инъекции, проблемы с авторизацией, утечки данных.
	- Без remote `origin` не работает.
- /simplify
	- Багов не ищет, только чистка: переиспользование готового, упрощение, эффективность.
	- Исправления применяет сразу.
- Ревью на GitHub
	- Для тарифов Team и Enterprise: Claude сам смотрит PR и оставляет комментарии к строкам.
	- Запустить вручную — комментарий `@claude review` в PR.
	- `REVIEW.md` в корне репозитория — правила только для ревью: что считать важным, что пропускать. Локальный `/code-review` его не читает.
	- Подключение — см. [Github integration](Github%20integration.md).
- Советы
	- Ревьюить в свежем контексте: `/code-review` и так работает в субагенте, а не в той беседе, что писала код.
	- Начинать с `medium`, `max` — перед важным мержем.
	- Сначала без `--fix`: посмотреть находки и исправлять выборочно. Правки `--fix` не откатить через [/rewind](!rewind.md).
	- Одни и те же ложные срабатывания — объяснить в [CLAUDE.md](_CLAUDE.md.md), для ревью на GitHub — в `REVIEW.md`.
	- `/security-review` — перед PR, который трогает авторизацию, ввод пользователя, секреты.
