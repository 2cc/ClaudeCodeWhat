- `/code-review` — ищет баги в изменениях. Встроенный [skill](skills.md), есть на любом тарифе.
- `/review` — то же самое, другое имя.
- `/code-review ultra` — глубокое ревью в облаке.
- `/security-review` — ищет уязвимости.
- `/simplify` — не баги, а чистка кода.
- /code-review
	- Что смотрит
		- По умолчанию — коммиты ветки, которых нет в upstream, плюс незакоммиченное.
			- Нет upstream — сравнивает с `main` или с предыдущим коммитом.
		- Другая цель — аргументом после уровня и флагов: номер PR, ветка, путь или диапазон.
			- `/code-review 1234` — PR, `/code-review src/auth` — папка.
			- `/code-review main...my-feature` — ветка против ветки, `/code-review HEAD~15..HEAD` — последние 15 коммитов.
	- Что ищет
		- Прежде всего баги в логике.
		- В зависимости от модели и уровня — ещё и чистку: переиспользование готового, упрощение, эффективность.
		- Учитывает `CLAUDE.md`. `REVIEW.md` не читает: он только для ревью на GitHub.
	- Как работает
		- В фоне как [субагент](subagents.md): свой контекст, беседу не забивает. Находки приходят в беседу, когда готово.
		- Тратит лимиты тарифа, как обычная работа в сессии.
		- Claude может запустить его и сам: если попросить словами «посмотри мои изменения» или из запланированной задачи.
			- Запретить это, оставив команду себе, — в [settings.json](_settings.json.md): `"skillOverrides": {"code-review": "user-invocable-only"}`.
		- Свой skill с именем `code-review` запускается вместо встроенного. `/review` по-прежнему вызывает встроенный.
	- Уровень
		- `/code-review low` … `max` — тот же [/effort](!effort.md).
		- `low` — только то, в чём уверен больше всего. Меньше ложных срабатываний.
		- `medium` … `max` — охват всё шире, но может быть и неуверенное.
		- Без уровня берёт последний, который вводил руками, даже в прошлой сессии.
			- Не вводил ни разу — текущий effort сессии.
	- Флаги
		- `--fix` — после ревью применить исправления. Правки идут через режим разрешений.
			- Эти правки [/rewind](!rewind.md) не откатит, только git.
		- `--comment` — выложить находки в PR на GitHub комментариями к строкам или в MR на GitLab одной заметкой.
			- Для GitLab нужен `glab`. Нет его — находки просто выводятся в терминал.
		- `--max-findings <n>` — сколько находок показать вместо обычного лимита. `--max-findings all` — все.
			- Выбор запоминается. Вернуть обычное — `--max-findings default`.
- /code-review ultra
	- Глубокое ревью в облаке: много агентов-ревьюеров, каждую находку отдельно воспроизводят и проверяют.
		- Старое имя — `/ultrareview`.
		- Research preview: цены и условия могут поменяться.
	- Что смотрит
		- По умолчанию — текущую ветку против основной, плюс незакоммиченное. Состояние репозитория загружается в облако.
		- `/code-review ultra develop` — сравнить с другой базой: веткой, коммитом или тегом.
		- `/code-review ultra 1234` — PR на github.com. Облако само клонирует PR, с машины ничего не грузится.
		- `/code-review ultra проверь изменения в auth` — текст из нескольких слов становится пометкой, находки свяжут с ней.
		- Предел — около 500 файлов и 8000 строк изменений. Больше — откажет.
	- Как работает
		- Перед запуском показывает охват, остаток бесплатных запусков и оценку цены.
		- Идёт в [фоне](фоновые%20задачи.md) 15–25 минут. Следить и остановить — `/tasks`.
		- Запускает только пользователь: Claude по своей инициативе его не стартует.
	- Цена
		- На Pro и Max — 3 бесплатных запуска на аккаунт, один раз, не обновляются.
		- Дальше — обычно $5–25 за ревью из usage credits, а не из лимитов тарифа.
		- Остановленный или упавший запуск всё равно съедает бесплатный.
	- Ограничения
		- Нужен вход через аккаунт claude.ai.
		- Через Bedrock, Google Cloud, Foundry, с ZDR или HIPAA вместо облачного запускается обычное локальное ревью.
	- Флаги
		- `--fix` — когда находки придут, применить их.
		- `--post` — для PR на github.com: выложить находки в PR одним комментарием от твоего аккаунта.
			- В окне запуска этот вариант будет выбран заранее, подтверждение всё равно спросит.
			- Сессию не закрывать до конца ревью: иначе ничего не выложится.
		- `--no-post` — не выкладывать, вариант с публикацией из окна запуска пропадает.
	- Из скрипта или CI — `claude ultrareview [PR или база]`: ждёт результата и печатает находки в stdout.
		- `claude -p '/code-review ultra'` для этого не годится: запускает ревью и выходит, не дождавшись.
- /security-review
	- Смотрит разницу между текущей веткой и основной веткой на `origin`.
	- Ищет инъекции, проблемы с авторизацией, утечки данных.
	- Без remote `origin` не работает.
- /simplify
	- Багов не ищет, только чистка.
		- Четыре агента параллельно: переиспользование готового, упрощение, эффективность, уровень абстракции.
	- Исправления применяет сразу.
	- Можно передать цель: путь или PR.
- Ревью на GitHub
	- Сервис для тарифов Team и Enterprise: Claude сам смотрит PR и оставляет комментарии к строкам.
		- Включает Owner организации в админке claude.ai, ставится Claude GitHub App.
		- Это не GitHub Action из [Github integration](Github%20integration.md): workflow-файлы не нужны.
		- Несколько агентов ищут проблемы в облаке Anthropic, отдельный шаг отсеивает ложные срабатывания.
	- Результат — комментарии к строкам, сводка и check run `Claude Code Review`.
		- PR не одобряет и не блокирует: check run никогда не падает.
		- 🔴 Important — чинить до мержа, 🟡 Nit — мелочь, 🟣 Pre-existing — баг был и до PR.
	- Когда запускается — настройка репозитория: при открытии PR, после каждого push или только по запросу.
		- Черновики и PR из форков сам не смотрит, только по команде.
	- Команды — комментарием в PR, нужны права на запись.
		- `@claude review` — одно ревью сейчас.
		- `@claude review always` — ревью сейчас и после каждого следующего push.
		- `@claude review stop` — отписать PR от ревью по push.
		- Если в репозитории есть и GitHub Action на `@claude`, команда запустит оба. Развести — через `trigger_phrase` у Action.
	- Глубина — Quick, Standard или Deep, на организацию или на репозиторий.
	- Платит организация из usage credits, по токенам. Месячный лимит трат — в админке.
	- `REVIEW.md` в корне репозитория — правила только для ревью: что считать важным, что пропускать, сколько максимум мелочей.
		- Читается из основной ветки, а не из изменений PR: сначала смержить.
		- Локальный `/code-review` его не читает. Общие правила — в `CLAUDE.md`, его читают оба.
- Советы
	- Ревьюить в свежем контексте: `/code-review` и так работает в субагенте, а не в той беседе, что писала код.
	- `/code-review` — по ходу работы, `ultra` — перед мержем крупного изменения.
	- Начинать с `medium`, `max` — перед важным мержем.
	- Сначала без `--fix`: посмотреть находки и исправлять выборочно. Правки `--fix` не откатить через [/rewind](!rewind.md).
	- На `high` и выше находок много — ограничить `--max-findings`, чтобы сначала разобрать главное.
		- Потом не забыть `--max-findings default`: лимит запоминается.
	- Репозиторий слишком большой для `ultra` — запушить ветку, открыть черновой PR и запустить `/code-review ultra <номер PR>`.
	- Одни и те же ложные срабатывания — объяснить в [CLAUDE.md](_CLAUDE.md.md), для ревью на GitHub — в `REVIEW.md`.
	- Ревью на GitHub для пробы — запуск при открытии PR или вручную: «после каждого push» умножает цену на число push.
	- `/security-review` — перед PR, который трогает авторизацию, ввод пользователя, секреты.
