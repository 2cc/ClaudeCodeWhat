- Режим разрешений определяет, что Claude делает сам, а на что спрашивает разрешение.
	- Режимы — основа. Поверх них работают правила `permissions` в [settings.json](_settings.json.md).
		- `deny` блокирует в любом режиме, даже в `bypassPermissions`.
- Как переключать
	- `Shift+Tab` по кругу: `manual` → `acceptEdits` → `plan` → `auto`.
		- Из `auto` первое нажатие ведёт в `manual`.
		- `bypassPermissions` встаёт в круг перед `auto`, только если его включили при запуске.
		- `dontAsk` в круг не попадает никогда.
	- Текущий режим виден под полем ввода: `⏸ manual mode on`, `⏵⏵ auto mode on` и т.п.
	- При запуске: `claude --permission-mode <режим>`.
	- По умолчанию: `permissions.defaultMode` в [settings.json](_settings.json.md).
		- `auto` и `bypassPermissions` из проектного `.claude/settings.json` не применяются — только из `~/.claude/settings.json`.
- С какого режима стартует сессия
	- В терминале и VS Code — `auto`, начиная с версии 2.1.283.
		- Если auto недоступен (модель не та, отключён админом) — `manual`.
	- `claude -p` и Agent SDK — обычно `manual`.
- manual ^manual
	- Спрашивает перед правками, командами и сетью. Сам только читает.
	- В конфиге называется `default`, имя `manual` — синоним (с версии 2.1.200).
	- Исключение: то, что уже разрешено в `permissions.allow`.
	- В диалоге разрешения на команду есть пункт «Yes, and switch to auto mode».
- acceptEdits ^acceptEdits
	- Правки файлов в рабочей папке применяет без вопросов.
	- Без вопросов и простые файловые команды: `mkdir`, `touch`, `rm`, `rmdir`, `mv`, `cp`, `sed`.
	- Остальные команды по-прежнему спрашивает.
	- Удобно, когда задача понятна и правки потом всё равно смотришь в `git diff`.
- plan ^plan
	- Исследует и предлагает план, исходники не меняет.
		- Читает файлы и запускает команды для разведки.
		- Если auto доступен — команды проверяет классификатор, как в [auto](#^auto). Иначе всё кроме чтения спрашивает.
	- Включить на один запрос: начать его с `/plan`.
	- Готовый план Claude показывает с вариантами
		- «Yes, and use auto mode» — принять и дальше работать в auto.
		- «Yes, manually approve edits» — принять и подтверждать каждую правку.
		- «No, keep planning» — остаться в plan и сказать, что поменять.
	- По `Ctrl+G` план откроется в текстовом редакторе.
		- После сохранения файла Claude считает последней версией плана именно его.
	- Когда нужен план, а когда высокий [/effort](!effort.md): [plan VS effort](plan%20VS%20effort.md).
- auto ^auto
	- Действует без вопросов, но действия перед выполнением проверяет отдельная модель-классификатор.
		- Чтение и правки в рабочей папке идут без проверки. Проверяются команды и сеть.
		- По умолчанию классификатор — Sonnet 5, а не модель из [/model](!model.md).
	- Что блокирует
		- Скачать и выполнить код (`curl | bash`), отправить секреты наружу.
		- Деплой в прод, миграции, `terraform destroy`.
		- Force push, `git reset --hard`, `git clean -fd` — всё, что теряет незакоммиченное.
		- Удаление файлов, которые были до начала сессии.
	- Что разрешает
		- Обычный `push` в любую ветку текущего репозитория.
		- Установку зависимостей из lock-файлов, чтение `.env`, read-only HTTP-запросы.
	- Ограничения можно задать словами: «не пушь», «без деплоя, пока не посмотрю».
		- Классификатор перечитывает их из беседы, после [/compact](!compact.md) могут потеряться. Надёжно — `deny`.
	- Заблокировал 3 раза подряд или 20 за сессию — auto встаёт на паузу, Claude снова спрашивает.
	- При входе отключаются широкие разрешения вроде `Bash(*)` и `Bash(python*)`. При выходе возвращаются.
	- Нужна модель Opus 4.6 / Sonnet 4.6 или новее. Админ может отключить: `disableAutoMode`.
	- Компромисс между скоростью и безопасностью, а не гарантия.
- dontAsk ^dontAsk
	- Никогда не спрашивает: что не разрешено в `permissions.allow` заранее, то сразу запрещено.
	- Для запуска без человека: скрипты, CI, `claude -p`.
	- Включается только флагом `--permission-mode dontAsk`.
- bypassPermissions ^bypassPermissions
	- Никаких проверок, делает всё что угодно.
		- Кроме `deny`-правил и `rm` по критичным путям (`/`, `~`, рабочая папка).
	- То же самое, что флаг `--dangerously-skip-permissions`.
	- Войти можно, только если включён при запуске.
		- `--allow-dangerously-skip-permissions` добавляет его в круг `Shift+Tab`, но не включает.
	- Под root и `sudo` не запустится.
	- Только для изолированной среды без интернета и важных данных. Для меньшего числа вопросов есть [auto](#^auto).
- Защищённые пути
	- Запись в `.git`, `.claude`, `.vscode`, `.bashrc`, `.zshrc`, `.mcp.json` и подобные сама не одобряется ни в одном режиме, кроме `bypassPermissions`.
- Не режимы разрешений, но тоже «режимы»
	- Fast mode: `/fast`, та же модель отвечает быстрее.
	- Уровень размышления: [/effort](!effort.md), [ultrathink](ultrathink.md).
- Советы
	- Незнакомый проект или рискованная задача — начать в `plan`, потом выполнять в `auto`.
		- Мелкие понятные правки — сразу в `auto`, план только тормозит. Подробнее: [plan VS effort](plan%20VS%20effort.md).
	- Понятная задача, изменения всё равно смотрю в `git diff` — `acceptEdits` или `auto`.
	- Ограничения для `auto` задавать через `deny`, а не словами: слова теряются после сжатия.
	- Долгая задача — `auto` плюс [хук](hooks.md) с уведомлением: в `manual` Claude будет стоять и ждать.
	- `bypassPermissions` — только в контейнере без важных данных.
