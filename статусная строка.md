- Своя строка внизу экрана: модель, папка, ветка git, заполненность контекста, лимиты, стоимость — что захочешь.
- Это любой скрипт: Claude Code передаёт ему на вход JSON о сессии, а что скрипт напечатает, то и видно.
- Работает локально, токены не тратит.
- Встаёт отдельной строкой над встроенным футером, не заменяет его.
	- Но подсказки вроде `esc to interrupt` и `? for shortcuts` пропадают.
- Прячется на время меню помощи и запросов разрешений.
- Как настроить
	- Проще всего: `/statusline` и описать словами, например `/statusline покажи модель и процент контекста`.
		- Claude сам напишет скрипт в `~/.claude/` и пропишет его в настройки.
	- Убрать: `/statusline remove` или удалить ключ `statusLine`.
	- Руками: ключ `statusLine` в [settings.json](_settings.json.md) (пользовательском или проектном), скрипт сделать исполняемым (`chmod +x`).
		```json
		{
		  "statusLine": {
		    "type": "command",
		    "command": "~/.claude/statusline.sh",
		    "padding": 2,
		    "refreshInterval": 5
		  }
		}
		```
		- В `command` можно писать и сразу shell-команду, без файла скрипта.
		- Ключи `statusLine`
			- `type` — всегда `"command"`.
			- `command` — путь к скрипту или shell-команда.
			- `padding` — доп. отступ слева в символах, по умолчанию `0`.
			- `refreshInterval` — перезапускать каждые N секунд (минимум 1). Для часов и всего, что меняется само.
			- `hideVimModeIndicator` — `true` прячет встроенный `-- INSERT --`, если режим vim выводишь сам.
	- Готовые сборки с темами: [ccstatusline](https://github.com/sirmalloc/ccstatusline), [starship-claude](https://github.com/martinemde/starship-claude).
- Что приходит в скрипт
	- Сессия и модель
		- `model.display_name`, `model.id` — модель, см. [/model](!model.md).
		- `effort.level` — `low`…`max`, см. [/effort](!effort.md). Нет, если модель не поддерживает effort.
		- `thinking.enabled` — включено ли расширенное мышление.
		- `fast_mode` — включён ли fast mode.
		- `output_style.name` — текущий output style.
		- `vim.mode` — `NORMAL`, `INSERT`, `VISUAL`, `VISUAL LINE`. Только при включённом vim-режиме.
		- `agent.name` — агент при запуске с `--agent`.
		- `session_name` — имя из `--name`/`/rename` или сгенерированный заголовок.
		- `session_id`, `prompt_id` — id сессии и текущего запроса.
		- `transcript_path` — файл с транскриптом.
		- `version` — версия Claude Code.
	- Контекст
		- `context_window.used_percentage` / `remaining_percentage` — занято / свободно в процентах. Подсказывает, когда пора [/compact](!compact.md), см. [/context](!context.md).
			- Считается только по входным токенам, без выходных.
			- Может быть `null` в начале сессии.
		- `context_window.total_input_tokens`, `total_output_tokens` — токены в контексте по последнему ответу.
		- `context_window.context_window_size` — размер окна: 200000 или 1000000.
		- `context_window.current_usage` — разбивка последнего запроса: `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`.
			- `null` до первого запроса и сразу после [/compact](!compact.md).
		- `exceeds_200k_tokens` — больше ли 200k токенов в последнем ответе. Порог фиксированный, от размера окна не зависит.
	- Лимиты и стоимость
		- Подробнее про лимиты — [токены и лимиты](токены%20и%20лимиты.md).
		- `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` — сколько израсходовано от 5-часового и недельного лимита, 0–100.
			- `rate_limits` есть только на подписках Pro/Max (или с gateway) и только после первого ответа. Каждое окно может отсутствовать отдельно.
		- `rate_limits.*.resets_at` — когда окно сбросится, unix-секунды.
		- `rate_limits.spend_limit.*` — лимит трат за корпоративным gateway.
		- `cost.total_cost_usd` — примерная стоимость сессии по прайсу, со счётом может не совпасть. Обнуляется после [/clear](!clear.md).
		- `cost.total_duration_ms` — сколько сессия идёт.
		- `cost.total_api_duration_ms` — сколько из этого ждали API.
		- `cost.total_lines_added`, `cost.total_lines_removed` — сколько строк кода изменено.
	- Prompt cache
		- Появляется после первого ответа, считает только основной диалог, без [субагентов](subagents.md).
		- `prompt_cache.warm` — жив ли кэш.
		- `prompt_cache.hit_ratio` — доля чтений из кэша, 0–1.
		- `prompt_cache.ttl` — `"5m"` или `"1h"`.
		- `prompt_cache.expires_at` — когда остынет.
		- `prompt_cache.misses`, `last_miss_at`, `last_miss_cause`, `miss_causes` — промахи кэша и их причины (`tools_changed`, `system_prompt_changed`, `ttl_expired_5m`…).
		- `prompt_cache.recache_tokens_if_cold` — сколько токенов придётся заново закэшировать, если кэш остынет.
		- Остальное: `caching_observed`, `requests`, `expected_rebuilds`, `cache_write_tokens`, `miss_recache_tokens`.
		- То же видно в `/usage`.
	- Папки, git, PR
		- `workspace.current_dir` (он же `cwd`) — текущая папка.
		- `workspace.project_dir` — папка, где запустили Claude Code.
		- `workspace.added_dirs` — папки из `/add-dir`.
		- `workspace.repo.host` / `owner` / `name` — репозиторий из `origin`, см. [git](git.md).
		- `workspace.git_worktree` — имя git worktree, если папка в нём.
		- `worktree.name`, `path`, `branch`, `original_cwd`, `original_branch` — только в worktree-сессии, см. [worktrees](worktrees.md).
		- `pr.number`, `pr.url` — открытый PR для текущей ветки (в GitLab — MR), см. [Github integration](Github%20integration.md).
		- `pr.review_state` — `approved`, `pending`, `changes_requested`, `draft`.
		- `pr.kind` — `mr` для GitLab.
	- Чего нет в JSON
		- Ветки, `git status`, времени и т.п. — скрипт достаёт сам.
		- Медленные команды (`git status`) кэшировать в файл, иначе строка будет тормозить.
	- Поля, которых может не быть, читать с запасным значением: `jq -r '.rate_limits.five_hour.used_percentage // empty'`.
- Пример скрипта
	- Модель, папка и процент контекста, например `~/.claude/statusline.sh`:
		```bash
		#!/bin/bash
		input=$(cat)
		MODEL=$(echo "$input" | jq -r '.model.display_name')
		DIR=$(echo "$input" | jq -r '.workspace.current_dir')
		PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)
		echo "[$MODEL] ${DIR##*/} | ${PCT}% context"
		```
		- Проверить без Claude Code: `echo '{"model":{"display_name":"Opus"},"context_window":{"used_percentage":25}}' | ./statusline.sh`.
	- Посложнее — две строки, темп расхода лимитов, PR и worktree: [пример статусной строки](пример%20статусной%20строки.md).
- Что умеет вывод
	- Несколько `echo` — несколько строк.
	- Цвета — ANSI-коды, например `\033[32m` — зелёный.
	- Ссылки — OSC 8, кликаются по Ctrl+клик. Нужен терминал с поддержкой (iTerm2, Kitty, WezTerm).
	- Ширину терминала брать из `$COLUMNS` и `$LINES`: `tput cols` внутри скрипта не работает.
	- Коротко: длинное обрежется или некрасиво перенесётся.
- Когда обновляется
	- При старте и [возобновлении](!resume.md) сессии.
	- После каждого ответа Claude, после [/compact](!compact.md).
	- При смене [режима](режимы.md) и переключении vim.
	- Когда сбрасывается окно лимита или остывает кэш.
	- По таймеру `refreshInterval`, если задан.
	- Обновления склеиваются с задержкой 300 мс, а скрипт, который ещё не отработал, при новом обновлении отменяется.
- Строка для субагентов
	- Ключ `subagentStatusLine` — своя строка для каждого [субагента](subagents.md) в панели под полем ввода вместо `имя · описание · токены`.
	- На вход: `columns` и массив `tasks` — `id`, `name`, `status`, `description`, `model`, `effort`, `contextWindowSize`, `tokenCount`, `cwd` и др.
	- На выход: по JSON-строке на задачу — `{"id": "...", "content": "..."}`.
		- Не вывел `id` — останется строка по умолчанию.
		- Пустой `content` — строка скрыта.
- Советы
	- Начать с `/statusline` словами, потом допиливать скрипт.
	- Самое полезное: модель, процент контекста, ветка, лимиты.
	- Процент контекста подсвечивать цветом после порога, например 70%, — чтобы вовремя [сжать](!compact.md) или [очистить](!clear.md).
	- Скрипт держать в dotfiles, чтобы не настраивать заново на другой машине.
