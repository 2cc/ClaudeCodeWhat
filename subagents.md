- Субагент — отдельный Claude, которому основной отдаёт часть работы.
- У него свой контекст: читает файлы, ищет, гоняет команды у себя, а в основную беседу возвращает только короткий итог.
- Главная польза — основной контекст не забивается логами и содержимым файлов, которые больше не понадобятся.
- Встроенные
	- `Explore` — только читает: найти, где что лежит в коде.
	- `Plan` — собирает контекст для плана в режиме [plan](режимы.md#^plan).
	- `general-purpose` — может и искать, и менять.
- Как запустить
	- Обычно Claude решает сам: по описанию субагента понимает, что задачу лучше отдать ему.
	- Попросить словами: «Пусть субагент code-reviewer посмотрит мои изменения».
	- Точно запустить нужного: `@"code-reviewer (agent)" посмотри изменения в auth`.
	- Вся сессия как субагент: `claude --agent code-reviewer`.
	- По умолчанию субагенты работают в фоне, основная беседа не ждёт. Запущенного на переднем плане можно увести в фон по `Ctrl+B`.
- Свой субагент
	- `/agents` или попросить Claude: «Создай субагента в `~/.claude/agents/`, который…».
	- `~/.claude/agents/` — личные, `.claude/agents/` — проектные.
	- Пример файла: шапка с настройками, ниже — инструкция субагенту.
		```markdown
		---
		name: code-reviewer
		description: Проверяет код на качество и ошибки
		tools: Read, Glob, Grep
		model: sonnet
		---
		
		Ты ревьюер кода. Найди проблемы в качестве, безопасности и читаемости,
		по каждой дай конкретное предложение.
		```
		- `description` — по нему Claude решает, когда отдавать задачу. Писать коротко и конкретно.
		- `tools` — какие инструменты разрешены. Не указал — все, как у основного.
		- `model` — можно взять модель подешевле, например `haiku` для поиска. См. [/model](!model.md).
- Когда это лишнее
	- Нужно часто уточнять и поправлять — субагент не видит вашей переписки.
	- Этапы опираются на общий контекст: план → код → тесты лучше вести в одной беседе.
	- Мелкая точечная правка — запуск субагента дольше, чем сделать самому.
	- Субагент тратит те же лимиты, что и основная беседа, причём каждый читает файлы заново в своём контексте.
- Советы
	- Исследование отдавать явно: «используй субагентов, чтобы выяснить, как устроена авторизация» — основной контекст останется чистым.
	- Ревью — в субагенте: свежий взгляд без предубеждений беседы, которая писала код.
	- Ставить задачу полностью: субагент не видит переписку, всё нужное должно быть в формулировке.
	- Своим субагентам давать минимум `tools`: ревьюеру хватит чтения.
	- Своего проще начать через `/agents` с генерацией Claude, потом поправить руками.
