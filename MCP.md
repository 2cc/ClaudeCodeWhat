- Model Context Protocol
- Просто какие-то расширители для возможностий клода.
- Расход контекста
	- Полные описания инструментов подгружаются по требованию, постоянно в контексте только их имена.
	- Инструкции сервера, если он их присылает, целиком попадают в системный промпт. Бывают большими.
- Лишний сервер вредит не только контексту
	- Больше похожих инструментов — модель чаще берёт не тот: MCP вместо `gh`, лезет в почту без нужды.
	- Чужие данные в контексте — лишний путь для prompt-инъекции.
	- Локальный сервер — отдельный процесс: замедляет старт, бывают ошибки подключения.
- Советы
	- Подключать только нужные серверы. Сколько они реально занимают — смотреть в [/context](!context.md).
	- Редко нужные серверы (почта, календарь, Drive) отключать через `/mcp` или подключать на уровне проекта, а не глобально.
	- Есть CLI (`gh`, `aws`, `gcloud`) — часто проще и экономнее обойтись без MCP.
	- Чужой сервер — это чужой код и чужие данные в контексте. Ставить только из доверенных источников.
	- Серверы для проекта держать в `.mcp.json` в репозитории — у всей команды одинаково.
	- Как научить Claude пользоваться сервером — в [skill](skills.md), см. [какое расширение выбрать](какое%20расширение%20выбрать.md).
	- MCP оставлять там, где есть состояние и доступ. Пример — браузер через Chrome DevTools MCP: «зайди, залогинься, посмотри консоль» вместо описания ошибки словами. Остальное — через CLI.
		- Кирилл Мокевнин: переход с MCP GitHub на `gh` снизил расход токенов в десятки раз. Это чей-то замер, источник он не назвал.
