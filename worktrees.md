- Worktree — отдельная рабочая папка репозитория со своими файлами и своей веткой. История и `.git` общие с основной папкой.
- Зачем: несколько сессий Claude в одном репозитории, и правки одной не задевают другую. В одной делается фича, в другой чинится баг.
- В репозитории должен быть хотя бы один коммит, иначе не создастся.
- Запуск
	- `claude -w feature-auth` (или `--worktree`) — создаёт worktree и запускает в нём Claude.
		- Папка: `.claude/worktrees/feature-auth/` в корне репозитория.
		- Ветка: `worktree-feature-auth`.
		- Без имени Claude придумает сам, вроде `bright-running-fox`.
	- Вторая параллельная сессия — та же команда с другим именем в другом терминале.
	- Уже в сессии: попросить «работай в worktree», Claude создаст его сам.
	- `claude -w "#1234"` — worktree из PR с номером 1234. Кавычки нужны, иначе shell примет `#` за комментарий.
	- `.claude/worktrees/` стоит добавить в `.gitignore`.
- От чего ветвится
	- По умолчанию — от основной ветки на remote (обычно `main`), чистое состояние.
	- Чтобы взять текущую работу с незапушенными коммитами — в [settings.json](_settings.json.md):
		```json
		{
		  "worktree": {
		    "baseRef": "head"
		  }
		}
		```
		- Имя конкретной ветки сюда не указать. Для этого — вручную через git, см. «Вручную через git».
- Окружение
	- Worktree — свежий checkout: зависимостей нет, `.env` и прочих неотслеживаемых файлов тоже.
	- Зависимости — попросить Claude поставить или поставить самому в папке worktree.
	- `.worktreeinclude` в корне проекта — какие игнорируемые файлы копировать в каждый новый worktree. Синтаксис как у `.gitignore`:
		```text
		.env
		.env.local
		config/secrets.json
		```
- Выход
	- Изменений нет — worktree и ветка удаляются сами.
	- Изменения есть — спросит: оставить или удалить. Удалить — значит потерять всю работу в нём.
	- Оставил — при выходе Claude напишет команду для возврата: `claude --worktree <имя> --resume`.
- Субагенты в worktree
	- Чтобы параллельные [субагенты](subagents.md) не мешали друг другу правками — каждому свой worktree.
	- Попросить словами: «используй worktrees для агентов».
	- Или навсегда для своего субагента — `isolation: worktree` во frontmatter.
	- Временный worktree без изменений удаляется, когда субагент закончил.
- Что общее с основной папкой
	- Разрешения «Yes, and don't ask again» сохраняются в основной `.claude/settings.local.json` и действуют во всех worktrees.
	- Плагины, установленные для проекта.
	- Skills, агенты и команды из `.claude/`, если в worktree своих нет.
- Вручную через git
	- Нужно, если ветка уже есть или worktree надо положить вне репозитория.
	- Команды:
		```bash
		git worktree add ../project-feature-a -b feature-a   # новая ветка
		git worktree add ../project-bugfix fix-issue-456     # существующая ветка
		git worktree list
		git worktree remove ../project-feature-a
		```
		- Дальше `cd` в папку и `claude`.
- Советы
	- Один worktree — одна задача. Много параллельных сессий сложно ревьюить, обычно хватает двух-трёх.
	- Сразу настроить `.worktreeinclude`, иначе каждый новый worktree без `.env`.
	- Давать осмысленные имена: по ним потом `--resume`.
	- Перед выходом с изменениями закоммитить их: случайно выбранное «удалить» не вернуть.
