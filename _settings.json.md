- Файл с настройками Claude Code в формате JSON.
- JSON строгий: комментарий `//` или запятая после последнего элемента — ошибка, при запуске Claude покажет Settings Error.
- Правки подхватываются на лету, перезапускать сессию обычно не нужно.
- Какие файлы загрузились: `/status`, строка `Setting sources`.
- Где лежат
	- `~/.claude/settings.json` — глобальный.
		- Действует для меня во всех проектах.
		- Тема, модель по умолчанию, свои разрешения.
	- `.claude/settings.json` — проектный.
		- Действует для всех, кто работает в проекте, его коммитят в git.
		- Общие разрешения, [hooks](hooks.md), плагины.
	- `.claude/settings.local.json` — локальный.
		- Действует только для меня и только в этом проекте.
		- В git не попадает: Claude Code сам добавляет его в глобальный gitignore, когда создаёт файл. Если создал руками — добавить в `.gitignore` самому.
	- `managed-settings.json` — от организации, перебить его нельзя. В личном использовании не встречается.
- Кто главнее
	- Порядок от главного: managed → флаги командной строки → локальный → проектный → глобальный.
	- Обычный ключ (например, `model`) берётся из самого главного файла, где он задан.
	- Списки (например, `permissions.allow`) не перебиваются, а складываются из всех файлов.
- Что обычно настраивают
	- `permissions` — разрешения, см. «Разрешения».
	- `model` — модель по умолчанию. [/model](!model.md) тоже сохраняет выбор как модель по умолчанию.
	- `env` — переменные окружения для сессии.
	- `hooks` — [hooks](hooks.md).
	- `statusLine` — [статусная строка](статусная%20строка.md).
	- Часть настроек (тема, режим редактора) можно поменять через [/config](!config.md), он сам запишет их в файл.
- Разрешения
	- Блок `permissions`, в нём три списка правил:
		- `allow` — делать без вопросов.
		- `ask` — всегда спрашивать.
		- `deny` — запрещено.
	- Порядок проверки: `deny` → `ask` → `allow`, срабатывает первое совпадение. Запрет всегда сильнее разрешения.
	- Ещё ключи:
		- `defaultMode` — режим по умолчанию, см. [режимы](режимы.md).
		- `additionalDirectories` — папки вне проекта, к которым у Claude есть доступ.
	- Пример: lint и тесты — без вопросов, `.env` читать нельзя.
		```json
		{
		  "permissions": {
		    "allow": [
		      "Bash(npm run lint)",
		      "Bash(npm run test *)"
		    ],
		    "deny": [
		      "Read(./.env)",
		      "Read(./.env.*)"
		    ]
		  }
		}
		```
	- Как разрешить команду навсегда
		- На запросе разрешения выбрать «Yes, and don't ask again».
			- Правило запишется в `allow` в `.claude/settings.local.json` в корне репозитория.
			- Так сохраняются команды терминала и домены для загрузки страниц. Разрешение на правку файлов живёт только до конца сессии.
		- `/permissions` — список всех правил и файл, откуда каждое взято. Здесь же можно добавить или удалить правило.
		- Дописать правило в нужный `settings.json` руками.
			- Чтобы работало во всех проектах — в `~/.claude/settings.json`.
	- Как записывать правила
		- `Bash` — все команды.
		- `Bash(npm run build)` — ровно эта команда.
		- `Bash(npm run *)` — всё, что начинается с `npm run`.
			- Старая запись `Bash(npm run:*)` значит то же самое.
			- Пробел перед `*` важен: `Bash(ls *)` не пустит `lsof`, а `Bash(ls*)` пустит.
		- Составные команды (`&&`, `;`, `|`) проверяются по частям: `Bash(npm *)` не разрешит `npm test && rm -rf build`.
		- `Read(./.env)`, `Edit(src/**)` — файлы, шаблоны как в `.gitignore`.
			- `//path` — от корня диска.
			- `~/path` — от домашней папки.
			- `path` или `./path` — от текущей папки.
			- `/path` — не от корня диска, а от файла настроек: в проектном — от папки проекта, в глобальном — от `~/.claude`.
		- `WebFetch(domain:github.com)` — загрузка страниц с домена.
		- `mcp__github` — все инструменты [MCP](MCP.md)-сервера `github`, `mcp__github__get_issue` — один инструмент.
	- Подводные камни
		- `allow` из проектного файла начинают работать, только когда папке доверились (диалог при первом запуске в ней). `deny` и `ask` работают сразу.
		- `ask` из проектного файла локальный `allow` не перебьёт: Claude так и будет спрашивать.
		- `Read` и `Edit` не остановят скрипт, который сам открывает файлы, например на Python. Для жёсткой изоляции нужна песочница (sandbox).
		- Правила соблюдает Claude Code, а не модель. «Не трогай `.env`» в [CLAUDE.md](_CLAUDE.md.md) — просьба, а `deny` — запрет.
- Советы
	- Командное — в `.claude/settings.json` в git, личное и эксперименты — в `settings.local.json`.
	- Разрешать точечно, не `Bash(*)`: `Bash(npm run test *)`, а не `Bash(npm *)`.
	- Иногда просматривать `/permissions` и удалять накопленные лишние правила.
	- Токены и пароли в `env` — только в локальный или глобальный файл, не в коммитящийся `.claude/settings.json`.
	- `/fewer-permission-prompts` — встроенный skill: смотрит историю и сам предлагает список `allow`.
	- После ручной правки проверить JSON: `jq . ~/.claude/settings.json`.
